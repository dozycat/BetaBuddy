# iOS 骨架背景误检回归（构建 2）

用户提供的 11.67 秒竖屏录屏，592×1280，视频轨道为单位变换。构建 1 的 iOS 分析在第 9 秒输出的髋部位于右上方背景管道，已在模拟器同一分析管线复现，因此不是播放层的 letterbox 映射问题。

## 修改

- 恢复原后端的检测、存在及跟踪阈值 0.5（iOS 构建 1 改为 0.6）。保持相同 Full float16 权重、CPU、10/15 FPS、720/960 输入上限。
- 仅保留双肩及双髋可靠且在画面内的采样，防止残缺背景检测被绘制。无可靠当前帧时显示「暂未可靠识别」。这不能保证消除所有高置信度误检。
- 将视频轨道的左上角坐标变换转换为 Core Image 的左下角变换。原实现对 ±90° 与转置镜像视频存在方向差异；这是额外发现的问题，不是本次单位变换录屏的原因。
- 新增「重新分析骨架」，原片、记录 ID、日期、笔记与完攀状态保留；取消或失败不替换旧分析。

## 实测与验证

- 用户原视频：日常档 65/117 个采样帧保留，细看档 99/175；第 9 秒双档髋部均在人物区域（x 0.40–0.60，y 0.30–0.50）。两档保留帧均没有髋部落入顶部 y<0.2 区域。其余未检测帧不画骨架，仍有漏检。
- 输入增大到 1280、改用原始 CVPixelBuffer 均未独立解决问题，未保留这些实验修改。
- 同 Full 权重的 Python 0.10.21 / 原版阈值 / 原始分辨率 / 逐帧 CPU 对照也有漏检与少量背景误检；不能声称此视频原版每一帧都正确。
- 6 种方向逐像素比较系统 AVAssetImageGenerator 的播放方向。修复前 ±90° 和转置镜像三个案例失败（32×32 RGB MAE 44.46），修复后全通过。
- 8 个核心几何测试、9 个 iOS 单元/视频集成测试通过；补充了已有记录重算后保存最新笔记的验证，并运行导航 UI 回归。
- 模型 SHA-256：5134a3aad27a58b93da0088d431f366da362b44e3ccfbe3462b3827a839011b1，未更换或修改模型。

原始私有视频不纳入源码。可选测试 testLocalRegressionVideo 从 /tmp/bb-regression.mp4 读取，缺失则跳过。第 9 秒检测输出叠加预览位于 ios/build/validation/fixed-frame-9s.png（构建输出，不纳入源码）。这是模型结果可视化，不是已完成真机测试的证明。
