# BetaBuddy iPhone · 岩馆

## 这是什么

「岩馆」入口：一家真实岩馆的 3D 还原，按线路筛选，选一条线，再看不同身材的人可能怎么爬它。场馆模型、线路和模拟来自一个独立的**场馆数据包**，随安装包内置，在手机上离线打开。

回看回答的是「我这一趟是怎么爬的」，岩馆回答另一半：「这条线，换个身材会怎么爬」。回看之后去岩馆找同一条线，看看别的解法；在岩馆看完，再去爬一次。两边都不打分，也都不替你下结论。

它不是官方场馆应用，不是线路数据库，也不是教练。

## 入口与导航

- 底部导航第一项 **岩馆**（岩馆 / 攀爬册），应用打开就落在这里。
- 「设置与关于」：说明页和无数据包页的右上角有按钮；进入 3D 页面后，顶部条属于数据包，原生不在上面叠按钮，入口是底部导航最右的齿轮。
- **关于**（从攀爬册右上角进入）：有数据包时列出下面的诚实性说明、场馆名、线路数、数据版本与生成日期；没有时用一句话说明这个构建不含岩馆数据。
- 岩馆页面在应用存活期间只创建一次。切到别的入口再回来，场景和已选线路还在。

### 尚未实现：把一趟攀爬关联到一条线

标记一段视频时，可以选「这是岩馆里的哪条线」。攀爬记录只多存两个字段：线路 id 和线路名称。回看页显示线路名，点击后让岩馆打开这条线。数据包换版本后 id 找不到时，保留名称，只是不能跳转。

接口两端已经就位：页面选中线路时把 id 和名称告诉应用，应用可以让页面打开某条线。存档结构、导入表单和回看页还没有这个字段。

## 主任务流

1. 第一次进入：一页说明。场馆名、线路数、数据版本，一句话讲清楚能做什么，然后是五条诚实性说明。点「知道了，进入岩馆」后不再出现，之后在「关于」里可以重读。
2. 进入：页面占满导航以上的全部区域，延伸到状态栏下方。顶部安全区由页面自己留出；底部是原生导航，页面不需要为 Home 指示条留白。
3. 找线：在 3D 场馆里转动、选墙、按线路筛选。这些都在数据包的页面里完成。
4. 看爬法：选一条线，换一个身材，看模型推演的动作序列。
5. 去爬：带着一个想试的改变上墙，录下来，在攀爬册里回看。

## 状态

| 状态 | 什么时候 | 界面 |
| --- | --- | --- |
| 无数据包 | 构建里没有 `GymPack/`，例如克隆公开仓库自己编译 | 入口保留。说明卡片：「这个构建没有内置岩馆数据」，加一句解释，并说明其余功能不受影响 |
| 数据包不完整 | 清单读不了、格式版本过新、清单列出的文件缺失 | 说明卡片：「岩馆数据不完整」，原因，「请重新安装完整版本」 |
| 加载中 | 页面还没完成加载 | 纸白底、进度圈、「正在打开岩馆…」。页面此时不可见，避免白屏闪烁 |
| 加载失败 | 页面加载出错、页面报告无法继续、网页进程被系统回收、离线保护没能启用 | 说明卡片写出原因，「重新加载」按钮 |
| 正常 | 页面加载完成，或页面发来就绪消息 | 只有页面本身 |

没有数据包不是错误，不弹窗，不崩溃，不留空白页。

## 诚实性说明

这五条在第一次进入前完整展示，文字是界面的一部分，不折叠成小字：

1. 非官方整理，与场馆没有合作或授权关系。
2. 岩点位置和线路由爱好者根据公开视频整理，可能与现场不符，也可能已经换线。以现场为准。
3. 「不同身材怎么爬」是模型推演，不是教练建议，不保证动作可行或安全。
4. 难度档来自线路牌色条，不是定级结论。
5. 场馆数据随安装包内置，在手机上打开；不联网，不上传。

延续已有的原则：不出现「最优解」「成功率」「适合你」这类没有验证过的说法。页面里的措辞由数据包负责，但要遵守同一条线。原生界面不复述模拟结果。把自己的一趟攀爬放进人体模型里比较，只发生在数据包的视频分析页面里（见下文「视频分析页面」）；那一页自己写明岩点、墙面和动作是从视频里自动认的、会认错，数字是相对值，不是教练意见。原生不转述它的结论。

## 数据包接口约定

这里只规定原生壳和数据包之间的接口。场馆数据的内容、格式和模拟的做法不属于这个仓库，也不在这里描述。

### 归属

数据包里的一切（模型、线路、求解器、网页）在仓库之外生成和保管，**不进入这个 Git 仓库**。仓库只有原生壳、加载逻辑、界面、本约定和脚本。`ios/GymPack/` 被 `.gitignore` 忽略；测试用的清单是合成的。

### 目录

```
GymPack/
  manifest.json     必需
  index.html        入口。竖屏手机界面，只用相对路径加载同目录资源
  analysis.html     可选。视频分析页面；清单的 files 里没有它，就是这个包不支持视频分析
  capture.html      可选。拍摄页面；清单的 files 里没有它，应用内的相机照常能录，只是没有机位检查和岩点识别
  …                 页面需要的其他文件，全部列在 manifest 里
```

### manifest.json

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `schema` | 整数 | 接口版本，当前为 1。省略视为 1；应用不认识的版本按「数据包不完整」处理 |
| `packVersion` | 字符串 | 数据包版本，原样显示 |
| `generatedAt` | 字符串 | 生成时间，ISO 8601；界面只显示日期部分 |
| `gymName` | 字符串 | 场馆名，原样显示 |
| `routeCount` | 整数 | 线路数 |
| `entry` | 字符串 | 入口文件，省略为 `index.html` |
| `files` | 数组 | 每项 `{ "path": 相对路径, "sha256": 十六进制摘要 }`，可带 `bytes`。包含入口，不含 manifest 自己 |

也接受下划线写法（`pack_version`、`generated_at`、`gym_name`、`route_count`）、`gym.name`，以及 `files` 写成 `{ 路径: 摘要 }` 的对象。路径必须是包内相对路径，不含 `..`。

校验分两处：

- **安装时**（`install-gym-pack.sh`）：逐个文件核对 SHA-256；清单以外的文件拒绝安装；只拷贝清单列出的文件。
- **启动时**（`GymPack`）：读清单，确认格式版本，确认每个文件存在。不重算摘要，安装包此时已由代码签名保护。

### 页面 → 原生

`window.webkit.messageHandlers.gym.postMessage(消息)`。在普通浏览器里这个对象不存在，页面应先判断再调用。

| `type` | 其他字段 | 含义 |
| --- | --- | --- |
| `ready` | 可带 `packVersion`、`routeCount` | 模型和界面就绪，发一次。应用收起加载状态 |
| `openSettings` | 无 | 请应用打开「设置与关于」（语言在第一项）。可选；页面不发也不影响，底部导航的齿轮始终可用 |
| `hintSeen` | 无 | 首次手势提示已经看完或被跳过。应用把这件事记在本机，之后不再让页面显示提示 |
| `routeSelected` | `id`、`name`（字符串）；取消选择时省略 `id` | 用户选中了一条线。应用只保留 id 和名称 |
| `error` | `message`（给用户看的一句话） | 页面出错。在 `ready` 之前收到，说明场景没起来，应用盖上失败状态和「重新加载」；`ready` 之后收到的（例如要打开的线路 id 不存在）不遮挡页面，由页面自己提示 |

只接受主框架发来的消息；不认识的 `type` 和多出来的字段（如 `wall`、`grade`）忽略。页面不发 `ready` 也能用：页面加载完成同样会收起加载状态。

### 原生 → 页面

入口 URL 的查询参数：

| 参数 | 含义 |
| --- | --- |
| `hint=0` | 应用已经收到过 `hintSeen`，页面不要再显示首次手势提示。没收到过就不带这个参数 |
| `lang=<代码>` | 应用当前的界面语言（用户在应用内选的优先，否则跟随系统，都不匹配为 `en`），每次加载都带：`zh-Hans`、`zh-Hant`、`en`、`ja`、`ko` 之一。页面按它显示自己的文字；不认识的值按 `en` 处理 |

Debug 构建的启动参数 `-gymQuery "<查询串>"` 会把给定的查询串原样接在入口 URL 后面（排在 `hint`、`lang` 之后，例如 `gympack://local/index.html?hint=0&lang=en&sheet=half&tab=steps`），用来在模拟器里摆出界面状态截图；Release 构建忽略它。除 `hint`、`lang` 外的参数由页面自己定义，应用不解释。

页面在 `window.BetaBuddyGym` 上提供两个函数，应用在页面就绪后调用：

| 调用 | 含义 |
| --- | --- |
| `BetaBuddyGym.openWall(id)` | 打开某面墙 |
| `BetaBuddyGym.openRoute(id)` | 打开某条线 |

id 是页面自己在 `routeSelected` 里给出的字符串，应用不解释它。函数不存在时调用安静地失败。界面上还没有触发点，接口为「关联线路」准备。

### 视频分析页面

攀爬册回看页的「分析这一趟」打开的是数据包里的另一页 `analysis.html`。原生把一段视频里抽出来的画面和逐帧姿态交给它，它在页面里算完、显示结果，再把结果交回原生保存。页面不读文件、不发请求：数据全部经脚本调用进去、经消息出来。这里只写接口两端各做什么，不写页面怎么算。产品行为见 [product-design.md](product-design.md) 的「分析这一趟」。

- **有没有**：清单的 `files` 里列了 `analysis.html` 才显示入口。没有数据包、或数据包没有这一页时，回看页不出现这个按钮。
- **加载**：与入口页面同一种方式、同一个目录、同一套离线保护和内容安全策略，地址 `gympack://local/analysis.html?lang=<代码>`。每次打开新建一个网页视图，关闭即释放；岩馆的那个网页视图不受影响。全屏显示，页面自己留出安全区；原生在右上角叠一个「完成」，并在状态栏的位置垫一条纸白色，页面滚动时内容不会钻到状态栏下面。
- **消息通道**：仍是 `gym`。两个页面各有自己的网页视图和各自的消息解析，互不接收对方的消息类型。

页面 → 原生：

| `type` | 其他字段 | 原生怎么做 |
| --- | --- | --- |
| `analysisReady` | 可带 `packVersion` | 页面脚本就绪。有保存的结果就调用 `show`，没有就准备数据并依次调用 `begin`、`addFrame`、`addPoses`、`run` |
| `analysisProgress` | `stage`、`fraction` | 忽略；进度由页面自己显示 |
| `analysisResult` | `id`、`json`（字符串）、`climber`（对象），可能还有 `capture`（对象） | `json` 原样存成这条记录的结果文件，覆盖上一份；`climber` 里的数值记在本机偏好里。`capture`（包 1.9.2 起，只对带拍摄计划的记录）说计划用上没有：`{ used: true, start, finish }` 或 `{ used: false, reason }`，原生只认 `used` 是布尔值的，连同三个字符串记在这条记录上；`used` 为假时不算错误，结果照常保存，但记录上的话换成「分析好了。取景时标的岩点和起步、结束点这次没有用上：机位和取景时对不上。」，回看页的分析入口下面也写这一句。`id` 是 `begin` 给的记录标识，显示保存的结果时页面给的是空串；与当前记录不符的忽略。过大的 `json`（超过 8 MB）不保存 |
| `analysisSeek` | `t`（秒） | 关闭分析页，回看的视频定位到这一刻并暂停 |
| `analysisError` | `code`、`message` | 页面已经显示了说明。原生不保存结果，分析页保持打开 |
| `error` | `message` | 脚本错误。在 `analysisReady` 之前收到，说明页面没起来，原生盖上失败状态和「重新加载」；之后收到的只记入本机日志 |

不认识的 `type` 和多出来的字段忽略；只接受主框架发来的消息。

原生 → 页面，调用 `window.BetaBuddyAnalysis` 上的函数（页面发出 `analysisReady` 之后才调用）：

| 调用 | 原生给什么 |
| --- | --- |
| `begin(meta)` | `id`：这条记录的 id；`w`、`h`：视频按显示方向的像素宽高；`climber`：上一次 `analysisResult` 带回来的参数，没有就不带这个键 |
| `addFrame(index, t, jpegBase64)` | 打开分析页时从原片现抽的画面：整段均匀取约 60 张，短边约 540 像素（竖屏即宽 540），方向已转正（与姿态的画面坐标一致），JPEG 质量 0.7，base64。只在内存里，不落盘；解不出来的画面跳过 |
| `addPoses(array)` | 保存的姿态，每批 40 帧：`{ t, img: [[x, y, visibility] × 33], lm: [[x, y, z, visibility] × 33] }`。`img` 是归一化画面坐标，`lm` 是同一帧的 world landmarks；只给检测到人、并且存有 world landmarks 的帧 |
| `run()` | 数据给完，开始计算 |
| `show(json)` | 把保存的结果原样传回，作为一个字符串 |

`begin(meta)` 另有一个可省略的键 `capture`：用应用内相机拍的记录保存着拍摄页面给的拍摄计划（见下文「拍摄页面」），原样作为字符串带上；导入的记录和旧记录不带这个键。不认识它的数据包会忽略。

用应用内相机拍的记录保存后会自己排队分析：姿态识别完成后，原生新建一个看不见的网页视图（放在窗口里、被原生界面盖住，尺寸与一屏相当），走与上表完全相同的步骤，拿到第一条 `analysisResult` 就保存并释放网页视图；收到 `analysisError`、页面没起来或十分钟没有结果则放弃。相机在用或应用在后台时不做。

每个参数都经 JSON 编码成为脚本里的字面量，不手工拼引号。函数不存在时调用安静地失败；`begin` 不存在时原生显示失败状态。`json` 的内容是页面自己的格式，原生不解析；页面读不了旧格式时会发 `analysisError`，用户用「重新分析」重来。

### 拍摄页面

攀爬册的「拍一趟」用到数据包里的第三页 `capture.html`。这一页没有界面：相机预览、提示、岩点描边和按钮都由原生画，页面只收画面、发消息。它怎么判断不属于这个仓库，这里只写两端各做什么。产品行为见 [product-design.md](product-design.md) 的「拍一趟」。

- **有没有**：清单的 `files` 里列了 `capture.html` 才加载。没有时相机照常录像和保存，界面上写明没有机位检查和岩点识别。
- **加载**：与另外两页同一种方式、同一套离线保护，地址 `gympack://local/capture.html?lang=<代码>`。每次打开拍摄界面新建一个网页视图，关闭即释放。它按整屏大小放在拍摄界面的最底下，被原生界面完全盖住：这样它和一张正常显示的页面没有区别，不会因为“看不见”而被放慢。消息通道仍是 `gym`，有自己的消息解析。
- **坐标**：画面上的位置都是相对于交给页面的那一帧的归一化坐标，`x` 向右、`y` 向下，0–1。原生把预览按原比例完整显示，所以可以直接换算成屏幕位置。

原生 → 页面，调用 `window.BetaBuddyCapture` 上的函数（页面发出 `captureReady` 之后才调用）：

| 调用 | 原生给什么 |
| --- | --- |
| `begin(meta)` | `id`：这一次取景的标识（每拍一趟换一个）；`w`、`h`：之后交来的帧的像素宽高；`fovH`：这些帧的水平视场角（度）。相机报告的是当前格式长边方向的角度；原生在相机开始出画面之后读它（之前读到的可能是预设生效前的格式），再按交出去的帧自己的宽高比换算到短边（从 4:3 的传感器裁出 16:9 的帧时长边不变）。没有在真机上核对过数值；不知道就不带；`venue`：用户选的岩馆如果是数据包里的一家，带它的岩馆 id，否则不带。清单的 `venues[].directoryIds`（包 1.9.1 起）列着这家岩馆在离线目录里的 id：用户从目录里选的岩馆按 id 找，找不到就是不在包里。清单没有这个字段的旧数据包、以及用户手填的馆名，才按名字判断：目录条目写作「品牌（分店）」，`venues[]` 里恰好有一家的 `name` 或 `names` 同时包含这两部分才算。用户换了岩馆、对应的岩馆 id 变了，就再调一次 `begin` |
| `addFrame(t, jpegBase64, info)` | 只在取景时，每秒 2 帧；上一帧还没交完就跳过。开始录像（`lock()`）之后不再交帧，实时姿态也停。画面方向已转正，短边缩到 360 像素（在处理器上缩，不经过 Core Image），JPEG 质量 0.7，base64；`t` 是从第一帧起算的秒数。`pitch`、`roll`（度）和 `shake`（弧度/秒，上一帧以来角速度的均方根）来自 Core Motion 的重力方向和角速度，真机上每一帧都带；手机接近平放、无所谓歪不歪时 `roll` 给 0。模拟器没有运动传感器，这三项不带（Debug 构建可以用启动参数给一组固定值）。方向按约定：`pitch` 镜头朝上为正，`roll` 以用户看屏幕时的顺时针为正。Core Motion 的重力向量在设备坐标系里（x 向屏幕右、y 向屏幕上、z 朝用户）是 `g`，则 `pitch = asin(g.z)`、`roll = atan2(g.x, −g.y)`，与约定里按画面坐标写的式子是同一件事。有单元测试，没有在真机上对过。`pose` 是随应用提供的姿态模型在这一帧上认出的 33 个 `[x, y, visibility]`，没认出人就不带；连续几帧平均超过 150 毫秒，或手机发热，这一次取景之后就不再跑姿态 |
| `setColor(key)` | 用户点了一个颜色（`palette[].key`）；再点一次同一个颜色传 `null` |
| `tap(x, y, role)` | 用户点了画面上的一处，`role` 是当时选中的那一项：`start_hand`、`start_foot`、`finish`、`hold`、`none`。页面返回它找到的岩点 id；什么也没返回，原生就在提示里写几秒「这里没有认出岩点」。改动随下一条 `captureAssessment` 显示 |
| `resetTaps()` | 用户选了「恢复自动识别」 |
| `rejectRoute(id)` | 包 1.9.1 起。用户对认出来的线路点了「不是这条」，`id` 是当时显示的那条线的 id。页面有这个函数时，它从下一条回复起改报下一条候选或不再报；页面没有这个函数（旧数据包）时调用安静地失败。两种情况下原生都记下这个 id：这一次取景里不再显示它，也不随记录保存。`begin` 之后原生和页面都从头算 |
| `lock()` | 开始录像的同时调用，录像不等它的回执。只在页面已经按当前这一次取景、当前选的岩馆 `begin` 过时才调用；刚换了岩馆、新的 `begin` 还没发出去就按了录像，不调用，这一趟不带拍摄计划 |

页面 → 原生：

| `type` | 其他字段 | 原生怎么做 |
| --- | --- | --- |
| `captureReady` | 可带 `packVersion` | 页面就绪。下一帧到来时调用 `begin`，然后开始交帧。页面加载后 8 秒还没有发这条，原生按没有拍摄页面处理，不再为它准备画面；之后发了仍然接受 |
| `captureAssessment` | `ok`、`steady`、`score`、`issues[]`、`hint`、`palette[]`、`color`、`holds[]`、`start`、`finish`、`person`、`wall`、`t`，可能还有 `route` | 画提示、指示条、颜色、岩点描边和起步 / 结束标记。只在取景时接受；录像开始后收到的忽略 |
| `captureLocked` | `id`、`plan`（字符串）、`summary`（对象） | `plan` 原样留着，随记录保存成 `<记录 id>.capture.json`；`summary` 里的颜色、岩点数、起步手脚点数、有没有结束点、当时是否合格和问题代码存进记录。记录保存之后再收到（或再收到一份）会覆盖保存。`id` 与当前这一次不符的忽略；超过 4 MB 的 `plan` 不保存 |
| `captureError` | `code`、`message` | 只记入本机日志：有些只是一时的（一帧解不出来、某家岩馆的数据文件没取到），页面照常工作。界面看的是页面还在不在回话：取景时连着 5 秒没有收到 `captureAssessment`，提示改成「机位检查暂时用不了，照常可以录」，旧的判断不再留在画面上；又收到就恢复。这 5 秒只在原生一直在交帧的时候算：交帧停过（来电、进后台、相机停了），恢复之后重新计。还没看过一帧就开始录时的 `no_frames`：这一趟照常录、照常存，只是没有拍摄计划 |
| `error` | `message` | 脚本错误。在 `captureReady` 之前收到按页面没起来处理；之后只记日志 |

读 `captureAssessment` 时从宽：

- `issues[].code` 和 `move` 是代码，句子由原生按语言给。认识的代码和动作见 `CaptureGuidance`；不认识的代码显示通用的「换个机位试试」，不认识的动作不显示。`severity` 只要不是 `warn` 就当作会妨碍分析（录像前要问一句）。
- 没有 `ok` 时按有没有妨碍分析的问题来算；没有 `steady` 时当作画面还没稳；没有 `score` 就不画指示条；`hint` 为空时取 `issues` 的第一条。`ok && steady` 才显示「机位可以」。
- `holds[]` 里没有 `poly` 的画 `box`，两样都没有的不画；`role` 不认识的当作普通岩点；`user` 为真的画实线，否则是虚线、起步 / 结束的标记带问号。有没有 `user` 为真的起步手点、结束点，决定界面引导用户下一步点什么。最多取 300 个岩点、每个多边形 96 个点、16 种颜色。
- `palette[]` 只用 `rgb` 画色块、用 `count` 写个数；`key` 只在 `setColor` 时传回去，不显示成颜色名。
- `route`（`captureAssessment` 和 `captureLocked.summary` 里都可能有）：`null` 或一个对象，页面认为这是数据包里的哪一条线。原生用到 `id`（线路的对外 id）、`conf`、`name`（页面按 `lang` 给的名字）、`nameZh`（线路自己的名字）、`grade`（难度文字，没有时是空串）；`colour`、`wall`、`others`、`otherRoutes` 和别的字段忽略。显示用 `name`，没有就用 `nameZh`，再没有（1.9.1 之前的数据包）才显示 `id`。它被显示成一个可以否掉的猜测；用户没有否掉的，`id` 和 `nameZh` 随记录保存（存线路自己的名字，不存译名）；存进记录的 `summary.route` 同样只留 `id`、`conf`、`nameZh`，页面按界面语言给的 `name`、`grade` 不落盘。对上之后岩点的 `id` 会换一批、补上的岩点只有 `box`：原生不依赖 `id`，没有 `poly` 的照常画 `box`。
- 难度：用户在这一次打开拍摄界面之后还没有自己选过难度时，认出的线路的 `grade` 如果正好是攀爬册用的写法（`V0`–`V12`），就填进难度并标明是自动填的；别的写法（各馆自己的色条说法，而且随语言变）只显示在线路名后面，不填。线路被否掉或不再认出来时，自动填的难度撤回。用户自己选过之后不再改动。
- `captureError` 的各个代码都不是致命的，见上表。

### 语言

应用的原生界面（进入前的说明、无数据包、加载中、失败状态）显示五种语言之一：用户在「设置与关于」里选的语言优先，没选就跟随系统。同一个语言代码通过 `lang` 交给页面，页面里的文字由数据包负责翻译。`manifest.json` 里的 `gymName` 是数据；数据包提供了 `gymNameLocalized` 时，应用按界面语言取对应的名称，否则原样显示。线路名、岩壁名同理，由数据包决定是否提供多语言。

用户在应用内改了语言时，应用用新的 `lang` 重新加载入口页面，页面就绪后调用 `openRoute(id)` 回到刚才选中的线路（id 来自上一次 `routeSelected`）。页面不需要自己记住语言，也不需要提供语言切换；如果想在自己的菜单里放一个「语言与设置」，发 `openSettings` 消息即可，应用会打开原生的设置页。

### 运行环境

- **加载方式**：页面不走 `file://`，而是由应用用自定义协议提供：入口是 `gympack://local/<entry>`，同目录资源照常用相对路径。这是一个普通的同源环境，`fetch`、`XMLHttpRequest`、ES module、three.js 的各类加载器、Blob URL 启动的 Worker（以及 Worker 里再 `fetch` 包内文件）都可用。
- 应用只回应数据包目录内真实存在的文件：路径在消去 `..` 并解析符号链接之后必须仍在包目录里，其他一律 404。主机名只有 `local`。
- 内容类型按扩展名给出：`html`、`js` / `mjs`、`json`、`css`、`glb`（`model/gltf-binary`）、`gltf`、`wasm`、`png`、`jpg`、`webp`、`svg`、`ktx2`、`txt`、`md`；`bin` 和其他扩展名为 `application/octet-stream`。文件以内存映射方式读取，大模型不会在应用进程里被整块复制。不支持 Range 分段请求。
- 每个响应带 `Cache-Control: no-store` 和内容安全策略：`default-src 'self' gympack: 'unsafe-inline' 'wasm-unsafe-eval' blob: data:; object-src 'none'; base-uri 'self'; form-action 'none'`。内联脚本与样式、Blob、`data:`、WebAssembly 可用；任何远程源、`eval` / `new Function` 不可用。
- 页面在任何情况下都拿不到网络：导航只允许 `gympack://local`，`http(s)`、`ws(s)`、`ftp` 的子资源和请求另由内容规则拦截。规则编译失败时页面不会打开。
- 不保留网站数据。`localStorage` 等在一次运行内可用，但不要依赖它们跨启动保存东西。
- 原生侧关闭了回弹、双指缩放、前进后退手势和链接预览，手势全部交给页面。
- 允许内联媒体播放。
- 状态栏文字是深色，页面顶部宜用浅色背景。只有竖屏。
- Debug 构建可以用 Safari 网页检查器连接；启动参数 `-gymOpenWall <id>` / `-gymOpenRoute <id>` 会在页面就绪后调用对应接口，用于截图和联调。加载耗时与页面报告的错误写入本机系统日志（类别 `gym`），不离开设备。

## 隐私

- 数据包在安装包里，不下载，不更新，不联网。
- 岩馆页面不能发起网络请求，这是由应用强制的，不依赖页面自觉。
- 应用不记录你看过哪面墙、哪条线，也不记录你在岩馆页面里选的身材参数。选中的线路只在内存里，退出即失。岩馆页面在本地只让应用记住两件事：你是否读过进入前的说明，以及页面的手势提示是否已经看过。
- 视频分析页面另外留下两样东西，都只在本机：每条记录的分析结果文件（里面有一张从视频里合成的墙面图），和页面上一次用的身高体重等参数（记在本机偏好里，下次分析时带上）。交给页面的画面只在内存里，不落盘；删除记录时结果文件一并删除。
- 拍摄页面拿到的是缩小的预览画面、手机的倾斜和晃动、可能还有人体关键点，都只在内存里；它交回的拍摄计划随记录保存在本机，删除记录时一并删除。拍摄页面和另外两页一样不能访问网络。
- 岩馆页面和分析页面不请求任何权限。应用内的相机请求相机权限（不请求麦克风）；按距离找岩馆在用户同意后取一次位置，只在本机排序，不保存。隐私清单：不追踪，不收集数据；因为录像前后要看剩余空间，多声明一项磁盘空间（E174.1）。

## 不做什么

- 不做账号、同步、排行、打卡、评论、线路评分。
- 不做在线更新数据包；换线之后要等下一个应用版本。
- 不做多场馆切换；一个安装包一个场馆。
- 原生不把模拟结果和用户视频的骨架叠在一起比较，也不据此评价用户的动作。视频分析页面里的对照由数据包负责，是相对比较，不是评价或建议。
- 不从用户视频里识别线路。关联线路实现后，也由用户自己选。
- 不在原生侧实现或复述求解逻辑；不把场馆数据放进公开仓库。

## 额外岩馆会员权限（iOS 1.5.0）

`banana-kerry` 保持免费；清单 `venues` 中其它岩馆使用现有终生会员的 StoreKit 已验证权益。会员状态不从页面、URL 或本地开关读取。页面切馆继续使用原有协议，原生导航代理拦截额外岩馆的 `venue`、带馆名前缀的 `route` / `wall` 查询，并打开会员页。购买或恢复成功后载入暂存的目标地址，取消时清除目标。退款／撤销通知到达时，已打开的会员岩馆回退免费馆。

`GymSchemeHandler` 同时拒绝未解锁岩馆在清单中列出的数据文件，不能只通过隐藏按钮控制访问。“更多”列表中的会员标识由宿主补充，数据包原文件和校验值不变。分析页默认使用同样的免费资源边界；未来若分析功能需要加载额外馆资源，必须显式传入已验证会员状态。
