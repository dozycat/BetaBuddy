# BetaBuddy iPhone · 岩馆

## 这是什么

第四个入口「岩馆」：一家真实岩馆的 3D 还原，按线路筛选，选一条线，再看不同身材的人可能怎么爬它。场馆模型、线路和模拟来自一个独立的**场馆数据包**，随安装包内置，在手机上离线打开。

BetaBuddy 原本只回答一个问题：「我这一趟是怎么爬的」。岩馆补上另一半：「这条线，换个身材会怎么爬」。回看之后去岩馆找同一条线，看看别的解法；在岩馆看完，再上墙试一次。两边都不打分，也都不替你下结论。

它不是官方场馆应用，不是线路数据库，也不是教练。

## 入口与导航

- 底部导航第四项 **岩馆**（上墙 / 攀爬册 / 练习 / 岩馆）。四项等宽，点击面积仍大于 44pt。
- **上墙**首页：有数据包时多一张卡片，写场馆名和线路数，点击进入岩馆。没有数据包时不出现，不占首屏。
- **关于**：有数据包时列出下面的诚实性说明、场馆名、线路数、数据版本与生成日期；没有时用一句话说明这个构建不含岩馆数据。
- 岩馆页面在应用存活期间只创建一次。切到别的入口再回来，场景和已选线路还在。

### 第二步（本版不做）：把一趟攀爬关联到一条线

标记一段视频时，可以选「这是岩馆里的哪条线」。攀爬记录只多存两个字段：线路 id 和线路名称。回看页显示线路名，点击后让岩馆打开这条线。数据包换版本后 id 找不到时，保留名称，只是不能跳转。

本版已经留好两端：页面选中线路时把 id 和名称告诉原生侧，原生侧可以让页面打开某条线。存档结构、导入表单和回看页没有改动。

## 主任务流

1. 第一次进入：一页说明。场馆名、线路数、数据版本，一句话讲清楚能做什么，然后是五条诚实性说明。点「知道了，进入岩馆」后不再出现，之后在「关于」里可以重读。
2. 进入：页面占满导航以上的全部区域，延伸到状态栏下方。顶部安全区由页面自己留出；底部是原生导航，页面不需要为 Home 指示条留白。
3. 找线：在 3D 场馆里转动、选墙、按线路筛选。这些都在数据包的页面里完成。
4. 看爬法：选一条线，换一个身材，看模型推演的动作序列。
5. 回到上墙：带着一个想试的改变去爬，录下来，回看。

## 状态

| 状态 | 什么时候 | 界面 |
| --- | --- | --- |
| 无数据包 | 构建里没有 `GymPack/`，例如克隆公开仓库自己编译 | 入口保留。说明卡片：「这个构建没有内置岩馆数据」，加一句解释，并说明其余功能不受影响 |
| 数据包不完整 | 清单读不了、格式版本过新、清单列出的文件缺失 | 说明卡片：「岩馆数据不完整」，原因，「请重新安装完整版本」 |
| 加载中 | 页面还没完成加载 | 纸白底、进度圈、「正在打开岩馆…」。页面此时不可见，避免白屏闪烁 |
| 加载失败 | 页面加载出错、页面报告无法继续、网页进程被系统回收、离线保护没能启用 | 说明卡片写出原因，「重新加载」按钮 |
| 正常 | 页面加载完成，或页面发来就绪消息 | 只有页面本身 |

没有数据包不是错误，不弹窗，不崩溃，不留空白页。

## 诚实性说明

这五条在第一次进入前完整展示，文字是界面的一部分，不折叠成小字：

1. 非官方整理，与场馆没有合作或授权关系。
2. 岩点位置和线路由爱好者根据公开视频整理，可能与现场不符，也可能已经换线。以现场为准。
3. 「不同身材怎么爬」是模型推演，不是教练建议，不保证动作可行或安全。
4. 难度档来自线路牌色条，不是定级结论。
5. 场馆数据随安装包内置，在手机上打开；不联网，不上传。

延续已有的原则：不出现「最优解」「成功率」「适合你」这类没有验证过的说法。页面里的措辞由数据包负责，但要遵守同一条线。原生界面不复述模拟结果，也不把它和用户的回看数据放在一起比较。

## 数据包接口约定

这里只规定原生壳和数据包之间的接口。场馆数据的内容、格式和模拟的做法不属于这个仓库，也不在这里描述。

### 归属

数据包里的一切（模型、线路、求解器、网页）在仓库之外生成和保管，**不进入这个 Git 仓库**。仓库只有原生壳、加载逻辑、界面、本约定和脚本。`ios/GymPack/` 被 `.gitignore` 忽略；测试用的清单是合成的。

### 目录

```
GymPack/
  manifest.json     必需
  index.html        入口。竖屏手机界面，只用相对路径加载同目录资源
  …                 页面需要的其他文件，全部列在 manifest 里
```

### manifest.json

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `schema` | 整数 | 接口版本，当前为 1。省略视为 1；应用不认识的版本按「数据包不完整」处理 |
| `packVersion` | 字符串 | 数据包版本，原样显示 |
| `generatedAt` | 字符串 | 生成时间，ISO 8601；界面只显示日期部分 |
| `gymName` | 字符串 | 场馆名，原样显示 |
| `routeCount` | 整数 | 线路数 |
| `entry` | 字符串 | 入口文件，省略为 `index.html` |
| `files` | 数组 | 每项 `{ "path": 相对路径, "sha256": 十六进制摘要 }`，可带 `bytes`。包含入口，不含 manifest 自己 |

也接受下划线写法（`pack_version`、`generated_at`、`gym_name`、`route_count`）、`gym.name`，以及 `files` 写成 `{ 路径: 摘要 }` 的对象。路径必须是包内相对路径，不含 `..`。

校验分两处：

- **安装时**（`install-gym-pack.sh`）：逐个文件核对 SHA-256；清单以外的文件拒绝安装；只拷贝清单列出的文件。
- **启动时**（`GymPack`）：读清单，确认格式版本，确认每个文件存在。不重算摘要，安装包此时已由代码签名保护。

### 页面 → 原生

`window.webkit.messageHandlers.gym.postMessage(消息)`。在普通浏览器里这个对象不存在，页面应先判断再调用。

| `type` | 其他字段 | 含义 |
| --- | --- | --- |
| `ready` | 可带 `packVersion`、`routeCount` | 模型和界面就绪，发一次。应用收起加载状态 |
| `hintSeen` | 无 | 首次手势提示已经看完或被跳过。应用把这件事记在本机，之后不再让页面显示提示 |
| `routeSelected` | `id`、`name`（字符串）；取消选择时省略 `id` | 用户选中了一条线。应用只保留 id 和名称 |
| `error` | `message`（给用户看的一句话） | 页面出错。在 `ready` 之前收到，说明场景没起来，应用盖上失败状态和「重新加载」；`ready` 之后收到的（例如要打开的线路 id 不存在）不遮挡页面，由页面自己提示 |

只接受主框架发来的消息；不认识的 `type` 和多出来的字段（如 `wall`、`grade`）忽略。页面不发 `ready` 也能用：页面加载完成同样会收起加载状态。

### 原生 → 页面

入口 URL 的查询参数：

| 参数 | 含义 |
| --- | --- |
| `hint=0` | 应用已经收到过 `hintSeen`，页面不要再显示首次手势提示。没收到过就不带这个参数 |

Debug 构建的启动参数 `-gymQuery "<查询串>"` 会把给定的查询串原样接在入口 URL 后面（与 `hint=0` 合并，例如 `gympack://local/index.html?hint=0&sheet=half&tab=steps`），用来在模拟器里摆出界面状态截图；Release 构建忽略它。除 `hint` 外的参数由页面自己定义，应用不解释。

页面在 `window.BetaBuddyGym` 上提供两个函数，应用在页面就绪后调用：

| 调用 | 含义 |
| --- | --- |
| `BetaBuddyGym.openWall(id)` | 打开某面墙 |
| `BetaBuddyGym.openRoute(id)` | 打开某条线 |

id 是页面自己在 `routeSelected` 里给出的字符串，应用不解释它。函数不存在时调用安静地失败。本版界面还没有触发点，接口为第二步准备。

### 运行环境

- **加载方式**：页面不走 `file://`，而是由应用用自定义协议提供：入口是 `gympack://local/<entry>`，同目录资源照常用相对路径。这是一个普通的同源环境，`fetch`、`XMLHttpRequest`、ES module、three.js 的各类加载器、Blob URL 启动的 Worker（以及 Worker 里再 `fetch` 包内文件）都可用。
- 应用只回应数据包目录内真实存在的文件：路径在消去 `..` 并解析符号链接之后必须仍在包目录里，其他一律 404。主机名只有 `local`。
- 内容类型按扩展名给出：`html`、`js` / `mjs`、`json`、`css`、`glb`（`model/gltf-binary`）、`gltf`、`wasm`、`png`、`jpg`、`webp`、`svg`、`ktx2`、`txt`、`md`；`bin` 和其他扩展名为 `application/octet-stream`。文件以内存映射方式读取，大模型不会在应用进程里被整块复制。不支持 Range 分段请求。
- 每个响应带 `Cache-Control: no-store` 和内容安全策略：`default-src 'self' gympack: 'unsafe-inline' 'wasm-unsafe-eval' blob: data:; object-src 'none'; base-uri 'self'; form-action 'none'`。内联脚本与样式、Blob、`data:`、WebAssembly 可用；任何远程源、`eval` / `new Function` 不可用。
- 页面在任何情况下都拿不到网络：导航只允许 `gympack://local`，`http(s)`、`ws(s)`、`ftp` 的子资源和请求另由内容规则拦截。规则编译失败时页面不会打开。
- 不保留网站数据。`localStorage` 等在一次运行内可用，但不要依赖它们跨启动保存东西。
- 原生侧关闭了回弹、双指缩放、前进后退手势和链接预览，手势全部交给页面。
- 允许内联媒体播放。
- 状态栏文字是深色，页面顶部宜用浅色背景。只有竖屏。
- Debug 构建可以用 Safari 网页检查器连接；启动参数 `-gymOpenWall <id>` / `-gymOpenRoute <id>` 会在页面就绪后调用对应接口，用于截图和联调。加载耗时与页面报告的错误写入本机系统日志（类别 `gym`），不离开设备。

## 隐私

- 数据包在安装包里，不下载，不更新，不联网。
- 岩馆页面不能发起网络请求，这是由应用强制的，不依赖页面自觉。
- 应用不记录你看过哪面墙、哪条线，也不记录身材参数。选中的线路只在内存里，退出即失。本地只记住两件事：你是否读过进入前的说明，以及页面的手势提示是否已经看过。
- 没有新的权限请求。隐私清单不变：不追踪，不收集数据。

## 不做什么

- 不做账号、同步、排行、打卡、评论、线路评分。
- 不做在线更新数据包；换线之后要等下一个应用版本。
- 不做多场馆切换；一个安装包一个场馆。
- 不把模拟结果和用户视频的骨架叠在一起比较，也不据此评价用户的动作。
- 不从用户视频里识别线路。关联线路（第二步）由用户自己选。
- 不在原生侧实现或复述求解逻辑；不把场馆数据放进公开仓库。
