## 当前状态（2026-11-13，1.1.0 (4)）

- **界面**：两个入口，岩馆在前、攀爬册在后；导入在攀爬册里。五种界面语言。
- **自动化**：Mac 上的核心测试 8 项通过；模拟器上单元与集成测试 28 项中 27 项通过、1 项按设计跳过（需要一段不在仓库里的本地回归视频）；界面测试 2 项通过（简体中文和英语各走一遍两个入口）。未签名的真机 Release 构建通过。
- **多语言**：String Catalog 里 132 个键在五种语言下都有翻译，占位符和换行数一致，由测试保证；键的清单与编译器导出的一致。繁体中文、英语、日语、韩语下的岩馆说明页、攀爬册、导入表单、关于页逐屏看过，没有发现漏翻和截断。回看页、分享文字和各类错误提示只核对了文字，没有在这四种语言下逐屏截图。译文没有经过母语者审校。
- **姿态识别**：模型权重与固定版本逐字节一致。管线在模拟器上用样片和一段真实竖屏录屏验证过，方向处理对 6 种视频方向逐像素核对过。仍有漏检；没有攀岩准确率的量化结论。
- **岩馆**：真实数据包在模拟器上安装、加载、选线、与应用互通消息都正常；离线保护有效。应用把界面语言通过 `lang` 交给页面；页面这一侧的多语言由数据包负责，这次看到的页面仍是简体中文。
- **真机**：开发签名的构建装到过一台 iPhone 上供验收，结果没有记录在这里。两入口加多语言的构建还没有上过真机。性能、发热、耗电、内存压力、长时间运行、最低系统版本、辅助功能，都还没有成文的真机结论。
- **分发**：构建 3 已上传但不提审；构建 4 尚未归档上传。状态见 [app-store/STATUS.md](app-store/STATUS.md)。

### 与网页实现所用模型的一致性

额外下载了 `legacy/web` 后端 `MODEL_URL` 指向的 `latest` 包进行比较。该包与固定 v1 包的外层封装哈希不同，但内部两个模型文件**逐字节一致**：

- `pose_detector.tflite`：`04f5a96483f8ce5913f8730ad2aa0c4c999c80a4b75653bc0e4712de18e104b2`
- `pose_landmarks_detector.tflite`：`82be6d591b9dad7d29fe21dc9fd892bf8b9602c458fb05209283de8282a0c488`

因此两边用的不只是同一个 Full 型号，实际的检测与关键点模型权重也相同。

### 手动模型样片

测试数据是 Google 的 `pose.jpg` 生成的 3 秒静态姿态视频，标题明确设为 **模型验证样片（非攀岩）**。实际通过相册选择器导入，得到 30 个采样帧，每帧 33 点，原片与结果一起保存在本地索引中。单次暖启动模拟器处理耗时约 1.26 秒，仅记录为 smoke test 事实，**不是 iPhone 性能基准或攀岩准确率证明**。

### 仍需真机与真实攀岩素材验收

本次没有宣称已完成以下检查：

1. **性能与能耗**：至少一台较旧 iPhone 与一台近期 iPhone，冷 / 暖启动、30 / 90 / 180 秒、1080p / 4K 原片；记录墙钟用时、峰值内存、Energy Log、热状态。对比 10fps / 720px 与 15fps / 960px，之后再决定是否引入 GPU delegate。
2. **攀岩准确性**：正面、背面、侧身、仰角、交叉腿、脚点遮挡、快速移动；人工标注关键片段，比较关键点误差、掉点比例、恢复耗时、候选片段误报和漏报。
3. **相机几何**：真实 iPhone 横竖屏与镜像、可变帧率、慢动作、HDR、不同视频编码。当前已实现 preferredTransform 与宽高比处理，但尚未覆盖全部真实录制组合。
4. **长期运行**：连续处理十段视频、低存储空间、设备锁屏、来电与后台切换、iCloud 原片不可达、文件选择器取消；验证内存释放与错误恢复。
5. **设备适配**：iOS 17 最低系统的真机、最大辅助字号、VoiceOver；截图和自动化主要在 iOS 26.5 模拟器完成。
6. **分发**：Apple 开发者签名、TestFlight / App Store 元数据与审核。这次验证时没有发布，也没有生成签名 IPA。

分析模型没有改权重、重新量化或攀岩微调。当前优化针对解码、采样、内存生命周期、主线程负载和本地持久化；没有与 `legacy/web` 的 Python 实现之间的性能或精度对比结论。
