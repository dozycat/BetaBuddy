## 2026-11-23（自动走一遍）· Debug 构建在没人能点屏幕的手机上自己走完拍摄（未发布）

真机能装、能带参数启动、能取文件，但没人去点。Debug 构建加了启动参数 `-debugCaptureAutopilot YES`（配合 `-debugOpenCapture YES` 一启动就进拍摄界面，这时应用直接从攀爬册开始）：它按人的顺序把拍摄界面走一遍，每一步调的就是界面上那个控件调的同一个函数，没有另一条路。Release 构建里没有这些代码（未签名 Release 的可执行文件里搜不到这些名字），也没有新增界面文字。

| 参数 | 作用 |
| --- | --- |
| `-debugCaptureAutopilot YES` | 打开自动走一遍 |
| `-debugCaptureGym <目录里的岩馆 id>` | 先选这家岩馆（和在表里点它一样）|
| `-debugCaptureColour <色板 key>` | 选这个颜色；不给就选岩点最多的那个 |
| `-debugCaptureTaps YES` | 页面已经猜了起步点也照样去点起步和结束（不给时只在页面没有起步点时才点）|
| `-debugCaptureSeconds <n>` | 录多少秒，默认 20 |
| `-debugCaptureBlind YES` | 页面认不出颜色时（比如手机镜头朝下放着）也照样录：跳过选颜色和标点，只为在没人操作时试一遍真相机的录像、保存和后续 |
| `-debugCaptureVideo <路径>` | 原有的参数；现在不以 `/` 开头的路径从应用容器算起，例如 `Documents/debug/clip.mp4` |

步骤：选岩馆 → 等页面就绪并给出非空的色板（30 秒等不到就停）→ 选颜色 → 等岩点（最多 15 秒）、记下页面报的线路 → 需要时点最低的那个岩点当起步手、最高的当结束点（走界面自己的点按处理，坐标是 0–1 的画面坐标，记下页面回的岩点编号）→ 按录像（出现「仍然开始录」的询问就答它）→ 录够秒数按停止 → 保存后的卡片留着，等姿态识别和分析页面跑完。每一步在 `session-*.jsonl` 里是一行 `event: autopilot`（`step`：`start`、`gym`、`ready`、`colour`、`holds`、`route`、`tap`、`marks`、`recordAnyway`、`recording`、`stop` / `stopped`、`saved`、`pose`、`analysed`、`done` / `failed`）。

### 第一次在真机上跑：按这个顺序看

用 Debug 构建装到手机上。长按画面上方那一行提示（约 1 秒）会在画面左上角叠一块调试数字，再长按收起；全程录一段屏幕，下面每一项都能从录屏里核对。不看屏幕也行：Debug 构建把同样的数字每秒一行写进应用容器的 `Documents/capture-diagnostics/`（见最上面「真机取证」一节），事后把这个目录取出来看。

1. **权限**：第一次点「拍一趟」出现相机权限的询问，文字是「拍下你的攀爬…」，没有麦克风的询问。拒绝后看到「没有相机权限」和「打开系统设置」。
2. **预览**：画面是正的（不是横着、不是倒着）、没有左右镜像（墙上的字是正的）、不裁边。
3. **位置**：没选岩馆时顶部下面有一行「按距离找附近的岩馆」；点了出现位置权限的询问，文字是「按距离推荐附近的岩馆…」。允许后这一行变成最近的岩馆（只知道车站的写成「可能在：…」）；拒绝后岩馆表里写着没有位置权限。
4. **调试数字第一行 `fovH`**：主摄竖着拿应该在 36°–45° 之间（按 16:9 的 1080p 格式算）。明显偏大（55° 上下）说明读到的是别的格式；`–` 说明没读到。`frame` 应该是 360×640。
5. **`pitch` / `roll` / `shake`**：手机竖直立着时 `pitch` 约 0、`roll` 约 0；把手机顶端朝自己倒（镜头抬起来看墙的上半部）`pitch` 变正；面对屏幕顺时针转 `roll` 变正；放稳后 `shake` 接近 0（小于 0.06），拿在手里晃明显变大。符号反了要改 `CaptureMotion`。
6. **提示跟不跟手**：把手机歪到 15° 以上，大约 1 秒后提示变成「手机歪了，把手机摆正」；仰到 45° 以上变成「手机仰得太厉害…」；晃动时「手机还在晃…」；摆正放稳后约 1 秒回到「机位可以，开始吧」。
7. **页面回话的快慢**：`replies` 应该稳定在 2.0/s 左右，`hand-over` 和 `prepare` 各在十几毫秒以内；`pose` 的耗时如果平均超过 150 毫秒会显示 `DROPPED`（实时姿态被放弃，不影响别的）。`replies` 明显低于 2 或者提示变成「机位检查暂时用不了」，说明盖在界面底下的网页视图被放慢了。
8. **描边对不对得上**：选一个颜色，虚线应该正好落在那些岩点上（不偏、不镜像、不缩放）；点一个岩点，变实线的就是点的那一个。对不上说明画面坐标和预览的换算有问题。
9. **录**：按录像，顶部开始计时，调试数字最后一行的 `frames` 每秒涨 30 左右、`dropped` 保持 0 或很小、`plan` 出现一个几十 KB 的数。录 1 分钟后停。
10. **录下来的文件**：在攀爬册里打开回看，画面是正的；在「设置 › 通用 › iPhone 储存空间」或用 Xcode 下载容器看这条记录的 `.mov`：每分钟多大（预期 HEVC 几十 MB），分辨率 1080×1920。
11. **发热**：连续取景加录像 5 分钟，摸一下机身；调试数字里 `pose` 有没有变成 `DROPPED`（发热时会放弃实时姿态）。
12. **存 → 分析**：停止后看到「已保存到攀爬册」，接着是姿态识别的进度，然后出现「看分析」。把手机接在 Mac 上用控制台看类别 `analysis` 的一行 `result kept; capture plan used …`：手机没动过应该是 `used true`。再试一次：按了录像之后把手机转一个角度，分析完记录上应该写着「取景时标的…这次没有用上」。
13. **中断**：录像中按 Home 回到桌面再回来，这一趟应该已经存好并写着「录像被打断了…」；录像中在多任务里划掉应用，重新打开后攀爬册里应该多出这一趟。
