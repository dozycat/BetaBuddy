# 相册归集、人物选择与剪辑进度

本轮在独立分支 `codex/camera-library-selection` 实现；完整目标包含以下三部分，不能以其中一项完成代替整个目标。

## 需要交付

1. 用户启用后，在授权的系统相册范围内自动发现并导入攀爬视频。识别室内／室外，支持纠正；以视频拍摄时间及视频的位置推荐岩馆，按天和馆自动聚合。不得用当前手机的位置猜旧视频的拍摄地点。扫描应可停止、增量恢复、去重，删掉的记录不能立即被扫描重新导入。兼容有限照片授权、拒绝／撤销授权、无位置／日期、云端原片不可用、资源被删除／编辑、存储失败和取消。系统相册原片不改动。
2. 自动选取攀爬者，并允许用户直接点选人、在其他时间纠正。采用轻量圈线，保留背景，不使用整幅压暗。选择必须影响姿态分析、跟拍和成片，不能只画 UI。多人交叉、遮挡、重新出现时不能悄悄换人；无法确认时保留缺失。选择和纠正随记录保存，重新分析仍有效，改选后旧分析／剪辑计划需要失效。
3. 用品牌已有的岩点轮廓和绳线表现剪辑进度，动作跟随真实工作进度。可取消、失败后重试，适配读屏、减少动态效果及大字号。不要做不断自行走满的假进度。

两端保持相同产品行为。平台权限及推理接口可以不同。攀岩识别／自动选人判断属于私有数据包；原生负责通用媒体读取、系统识别结果、交互、存储和渲染。不得把私有场馆和算法写进应用仓库。

## 2026-11-28 · iOS 相册链路

- 攀爬册入口「相册自动收录」，默认关闭。用户启用才请求 Photos 授权；支持有限授权的管理入口、拒绝／撤销提示、停止、返回前台重扫、相册变化增量检查。拍摄和后台期间停止扫描。未验证有限授权新增／撤销的完整系统界面。
- 串行读取已授权的本地视频，原片不改、不联网下载。匹配后复制视频、缩略图和 metadata；非匹配结果按资源版本及分类配置版本缓存；读取／保存失败不记为已处理。已导入标识与记录原子写入，删除记录后仍保留去重标识。手动导入取得相册标识时也登记，用户仍可手动重新导入。
- 视频拍摄日期用于分组。室内片段只用视频已有、精度可用的位置查询离线目录，保存最近的可用馆作为「推荐」；不获取当前手机位置，不存精确坐标。环境、馆和日期可在「整理这一趟」修改，修改后重新分组。
- 原生只执行通用图像编码和私有配置的向量比较。模型从本地安装且校验源文件 SHA-256，随应用打包；私有配置带开发标记，阈值尚未完成独立样本验证。无配置／模型的构建显示不可用，不替换成未经验证的系统标签。
- 核心 37 项通过。iOS 定向 22 项通过，包含存档兼容、失败回滚、不重复收录／删除后不回流、纠正环境、五语言，以及真实 PhotoKit 片段导入。初轮集成因模拟器权限跳过；授权后首轮暴露模拟器图形推理不兼容，模拟器改用 CPU，再跑通过。真实端到端同时检查实际视频副本、拍摄日期与再次扫描；素材仍只有一个真实正例，不代表分类准确率。
- PhotoKit 测试只在模拟器创建／复用一段参考片段，不修改既有相册项目。第一次测试清理时遇到系统删除确认，终止了该测试；后续改为复用同一个测试资源，不再在测试里删相册视频。

## 2026-11-28 · iOS 人物选择开发链路

- 回看页新增「选择攀爬者」。多姿态候选和粗略衣着色样在本机生成，自动选择由私有数据包决定。圈线保留原视频背景，可拖动时间、点选、自动选择、在另一个时刻纠正；取消不写入选择，保存后保留选人标记。
- 下游只接收所选候选的姿态。分析调用带通用的已选人标记，跟拍不再独立改选画面里的其他运动目标；缺失区间不补一个人进去。私有跟拍测试覆盖多个已选片段及中间全景段，未用它证明真实遮挡质量。
- 保存改选递增记录修订号。旧姿态任务及旧网页结果不能覆盖新选择；分析／剪辑缓存按修订号读取，退出或中断后旧缓存不会重新出现；删除记录也清理中断遗留的旧版本文件。选人时暂停后台姿态分析和相册扫描。
- 真实单人参考片段共 29.8 秒、298 个取样，当前策略选中 298 个。模拟器检测和解析约 5.2 秒，不能据此声称真机速度。真实数据包继续生成计划并由原生渲染成片，端到端通过；这个片段的计划没有推拉镜头，不能拿它证明真实跟拍稳定性。
- 点选 → 保存 → 重新打开 → 取消 → 删除本次测试记录的 UI 测试通过，已看截图：品牌色圈线、原背景、时间滑块和自动选择入口可见。单个清晰人物的界面证据不等于多人交叉验收。
- 暴露的问题：另一个 20 秒多人走拍片段有 80 / 200 个取样没检测到可靠躯干，策略没有自动确定人物；要求其自动选出的探索测试失败，原始失败保留。不能调低门槛把它写成通过，需要继续改善远景候选与手动纠正的可用性，并补真实遮挡／交叉素材。
- 核心 37 项通过；人物存储、旧结果拒收、多语言与已有存储定向检查通过；未签名设备构建通过。没有真机验收或 Android 选人实现。
- 仍需处理：长视频候选数据的内存峰值（独立存储进度见下节），跨遮挡的真实身份连续性、多人点选与跟拍成片的一致性、无可点候选时的手动入口，以及小屏／大字号／读屏。不能据当前证据标记完整目标完成。


## 2026-11-28 · 候选独立存储、手动圈选与 Android 基础链路

- iOS 多人候选已从总存档移到每条记录的压缩文件。打开选人页才在后台读取；总存档只留引用和选中的姿态。先写新文件，再原子提交引用；提交失败删新文件、保留旧选择；新引用提交后清理旧文件。已有开发存档会迁移。600 个候选取样的存储测试确认索引小于 3 KB，重开、读取、替换、删除和索引写入失败恢复通过。不是长视频内存性能验收。
- iOS 增加「未圈到？手动圈选」：在暂停画面拖动圈住全身，从这一刻向前／向后做局部姿态识别。只保留有实际检测的姿态，身份匹配仍由私有策略判断；部分片段缺失时有补选提示。识别失败不改先前保存的选择。
- 真实固定机位顶绳远景 20 秒：全图检测主要得到画面底部人物，自动策略没有选定目标。手动圈选能找回墙上目标，但只确认 17 / 200 个取样（0–1.7 秒），侧身后丢失；从第 1 秒圈选会向前和向后覆盖，共 10 / 200 个取样（0.4–1.4 秒）。这一段不能说成连续跟拍已解决。下一步需要把人物位置跟踪与姿态是否可见分开，保留遮挡空段但能在身份明确时继续；不能靠放宽身份条件硬接。
- iOS 圈选 → 保存 → 重新打开 → 删除本次记录的 UI 检查通过，截图已看：圈线落在墙上人物，背景保留。11 项存储／多语言检查、随后 2 项双向识别／旧结果拒收检查通过；核心 37 项和未签名设备构建通过。初次只有 1 个取样的失败结果保留，没有把后续「返回了一小段」当作质量验收。
