# Android 与 HarmonyOS 终生会员接入边界

用户已确定：**每个平台分别购买、分别恢复，不跨平台互通；本地价格尽量接近 iOS。** iOS 会员目前是一次性非消耗型商品，立即获得攀爬册标识，核心功能始终免费。Android 与 HarmonyOS 只有在真实商品、核验和退款流程连通后才能显示“已解锁”。

## Android 共通状态

- 商品不可用：说明对应商店暂时无法连接，提供重试；不能显示一个写死的价格。
- 可购买：从商店商品接口读取名称和本地化价格，明确说明一次购买、无订阅、该商店账号可恢复。
- 支付处理中：不重复发起购买；用户取消时不授予权益，也不显示错误的“失败”。
- 核验中：客户端传订单凭证到开发者服务端；服务端向商店查询订单状态，核对应用、商品、账号范围和撤销状态，返回有效权益后才显示标识。
- 已购买：启动、恢复入口、购买回调、回到前台时重新查询。重复回调须幂等。退款或撤销后移除标识。
- 离线：已经核验的权益可用受限期限的本地缓存改善体验，恢复与撤销核对必须重新联网；不能把本地布尔值当成永久购买凭证。

交易验证接口只接收支付所需的订单标识和渠道，不上传视频、姿态数据或攀爬记录。启用前同步更新应用内及网站隐私政策，说明对应支付 SDK、网络请求、保存期限和联系人。

## 小米

小米官方 IAP 文档支持非消耗型商品。实际接入依赖开发者账号、应用 ID、商务白名单、计费点和 SDK 下载。注册前不能获得可测试的真实商品与支付环境。账号就绪后：

1. 确认**普通应用**可使用的 IAP 合作和 SDK 版本；官方技术文档的示例多用“游戏”措辞，须以后台审批为准。
2. 配置非消耗型商品，客户端检查国内小米设备及支付环境，再查询商品；只有用户同意相应隐私条款后才初始化支付 SDK。
3. 使用 `createPurchase` 发起支付。收到 `PurchaseData` 后由服务端使用订单号和购买令牌查询状态，核验通过后再调用 `finishPurchase`。
4. 启动、恢复和未发货错误时查询历史及未完成订单，补发权益并完成订单；分页不能漏。退款和撤销按服务端最新订单状态处理。

官方资料：[IAP 开发准备](https://dev.mi.com/xiaomihyperos/documentation/detail?pId=2232)、[客户端与订单流程](https://dev.mi.com/xiaomihyperos/documentation/detail?pId=2239)、[服务端通知](https://dev.mi.com/xiaomihyperos/documentation/detail?pId=2238)。

## OPPO

OPPO 软件商店介绍包含支付能力和应用合作，但公开可检索的详细 SDK 文档主要是游戏支付。先在实名认证后台确认普通应用的应用联运／内购合作、SDK、商品类型、服务端核验、退款通知及价格配置，再实现 OPPO 渠道。不要把游戏 SDK 或小米 SDK 直接塞进通用包。

参考：[OPPO 应用分发与合作入口](https://open.oppomobile.com/product/page?page_name=appstore)。

## HarmonyOS 5+

HarmonyOS 原生 HAP 需要单独的华为商品和支付集成；不能使用 Android AAR，也不能把小米／OPPO 的订单当作华为会员。先完成可安装的 Stage 应用与核心功能，随后在华为开发者后台确认非消耗型商品及核验流程。会员页文案沿用上述权益边界。

## 发布验收

- 三个渠道分别验证：商品加载与价格、成功购买、取消、断网、重复回调、重启、同账号换机恢复、不同账号不恢复、退款撤销。
- 小米与 OPPO 的包使用新正式签名；旧 GitHub 测试包升级兼容性不属于这次发布范围。
- 任一渠道缺少真实购买或恢复验收时，不能把该渠道标为“iOS 能力已追平”。
